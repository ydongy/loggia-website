# v1.0 security walkthrough

Date: 2026-10-03, commit `81ff602` plus the documentation branch. Scope: what the site serves, its headers, its scripts, its dependencies, the repository history and the deploy configuration. Method: reading the generated files and configuration, the site's own checks, and pattern scans of the committed history. **This is a bounded review, not a proof of safety**: it was not an independent audit and it covers only the areas below.

## What was checked

| Area | What was inspected | Result |
|---|---|---|
| Content-Security-Policy | `public/_headers` and the generated pages (`check_site.py`) | `default-src 'self'`; styles and images only from the site; `connect-src` only `https://dl.useloggia.com`. No inline styles. `script-src` also allows `'unsafe-inline'` (see F1). |
| Other headers | `public/_headers` | `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer` on every response. |
| Third-party resources | Every `src`, `href` and `srcset` in `public/` and the three scripts | Only addresses on `useloggia.com`; the scripts contact only `https://dl.useloggia.com`. No fonts, analytics, widgets or embeds from other hosts. |
| Scripts | `public/lang.js`, `download.js`, `carousel.js` (about 5.7 KB in total) | No `eval`, no dynamic code, no DOM insertion of feed text as HTML (the download text is set with `textContent`); the download URL must start with `https://`. |
| Cookies and storage | The scripts | No cookies. `localStorage` holds only the chosen language. |
| Forms | Generated pages | None; contact is a `mailto:` link. |
| Redirects | `public/` and `check_facts.py` | No `_redirects` file; one address per page. |
| Deploy configuration | `wrangler.jsonc` | `workers_dev` and `preview_urls` off; the custom domain is bound in the dashboard. |
| Dependencies | Repository files | No Node dependency and no package manifest; Python standard library only; `scripts/sitekit/` is a vendored copy with its commit in `VERSION`. |
| Repository history | Every added line of every commit on all refs (46 commits) | 0 matches for key, token, private-key and secret-like patterns. |

## Findings

| # | Finding | Severity | Status and fix |
|---|---|---|---|
| F1 | `script-src` allows `'unsafe-inline'` although no generated page contains an inline script, so the policy is looser than needed. | Low | Open. Remove `'unsafe-inline'` from `script-src` in `public/_headers` after checking the live pages with the browser console open (`docs/adr/0004-content-security-policy.md`). |

## History scan

A case-insensitive pattern scan of the added lines of all 46 commits on every ref, covering assignments of long values to names containing key, secret or token, private key headers, and common token prefixes, found 0 matches. It was run by hand with `git log --all -p` and `grep`, not with a dedicated scanner; the generated site was scanned by reading, not with a tool. Result on 2026-10-03.

## Not covered

- The hosting account: Cloudflare settings other than `wrangler.jsonc` (access control of the dashboard, DNS, email routing rules, the Git connection).
- The release feed and the download bucket at `dl.useloggia.com`, including its CORS rules and what it serves.
- The behavior of the live site under the headers (the policy was checked statically, not against the deployed responses).
- Browser-specific behavior of the scripts beyond a desktop browser at desktop and phone widths.
- Dependencies of the tools run by `npx` for preview and deploy.

## How to repeat

```bash
python3 scripts/sitekit/check_site.py                       # pages, links, anchors, CSP violations
python3 scripts/check_facts.py                              # no _redirects, footer links
grep -rhoE '(src|href|srcset)="https?://[^"/]+' public | sort | uniq -c   # hosts used by the pages
grep -n "Content-Security-Policy" public/_headers
git log --all -p --no-color | grep -E '^\+' | grep -iE '(api[_-]?key|secret|token)["'"'"' ]*[:=]["'"'"' ]*[A-Za-z0-9_-]{20,}|BEGIN [A-Z ]*PRIVATE KEY|ghp_[A-Za-z0-9]{20,}'
```
