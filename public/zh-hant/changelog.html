更新記錄

1.3.0

2026-10-17

新增

  • Notifications when a published service goes down or works again, and when your services go offline or come back; changes you make in Loggia post nothing. Turn them off in Settings › General › Notifications
  • A QR code of a published service's public address, to open it on a phone: Show QR Code in the service's menu in the sidebar, or QR Code next to Copy in its details. It is made on this Mac; available on Free and Pro
  • Change… next to a service's address in its details moves it to another port, or between http and https; a published service keeps its domain and points it at the new address. Available on Free and Pro
  • cloudflared now updates itself two days after a new version comes out, with the same checks and undo as Update, and waits while something else is in progress. Turn it off in Settings › Connector
  • Trusted networks for access protection: visitors from a home or office internet address skip the email code. Add This Network adds the address this Mac is on. Pro; on Free they can still be removed

1.2.0

2026-10-16

新增

  • Send as localhost, a switch in a service's publish settings, for services that only accept requests addressed to localhost, like some development servers; off by default, and available on Free and Pro
  • Link details show the last 7 days hour by hour in a strip under the 7-day uptime; hover an hour to see its time and the share of checks that were up

修正

  • The check for a new cloudflared now runs in the background once a day, not only while Settings › Connector is open; when there is one, the link details offer the update
  • If a new cloudflared does not start after an update, Loggia now says it switched back to the previous version, or that cloudflared is not running if that one does not start either, instead of a generic failure
  • A single failed check no longer turns a service red: like the link status, it turns red after two checks in a row, so the service list, the menu bar and the link status agree
  • When cancelling or deleting a service after a failed publish cannot remove what it set up at Cloudflare, Loggia tries again later instead of leaving it behind
  • The cloudflared log no longer grows without limit: once it passes 10 MB, Loggia keeps the latest part and moves the earlier part to a second file, and Export Diagnostics includes both
  • If the file where Loggia keeps your services is damaged, Loggia sets it aside as a backup, and when it cannot, it no longer saves over it, so the only copy is not lost

1.1.1

2026-10-11

變更

  • Advice about proxy apps appears only when one is actually intercepting the connection, as one line saying what to set

修正

  • A published service showed as unreachable on this Mac while it opened fine elsewhere: the public check no longer goes through this Mac's name lookup
  • Right after publishing, the check and the built-in web page no longer look up the new domain on this Mac before it opens from the internet; a proxy app could remember it as missing for half an hour

1.1.0

2026-10-11

新增

  • Send Feedback, in the Help menu and the menu bar icon's right-click menu, opens a new email to support with your versions filled in
  • Help also has Loggia Support and Export Diagnostics, and Settings › About has Contact Support
  • Error messages that ask for diagnostics now say where to send them
  • Right-click the menu bar icon for Open Loggia, Settings, Restart cloudflared and Quit Loggia, so Loggia can be quit without a Dock icon
  • While cloudflared restarts from that menu the icon shows it; a failed restart says so and opens the link details
  • When cloudflared can't reach Cloudflare, a section that opens with a click lists what to set in a proxy app in enhanced or TUN mode: the domains to route directly and the fake-IP filter

變更

  • Link details call their last group Cloudflare & Connector, and the first publish step is Prepare Connector, matching the Settings tabs

修正

  • The sidebar showed a published service as working while the menu bar panel and its details showed it unreachable
  • The menu bar panel sometimes kept a blank band above and below its content after a problem cleared
  • The link details started too far down the window
  • The status lamp slid across the window when the sidebar was collapsed or expanded
  • The link details gave only a generic message when a proxy app left some connections working

1.0.0

2026-10-10

新增

  • Publish a local port or external URL as an HTTPS domain in one click; every step can be retried, and unpublishing leaves nothing behind on Cloudflare
  • Link health: which segment is down, why, and which button fixes it; colored status in the menu bar icon
  • Menu bar panel: one calm status line that grows into the cause and a mini chain only when something is wrong; copy and open buttons appear on each service when you hover it or focus it with the keyboard
  • Main window: the sidebar shows when the services were last checked; the status capsule stays in the toolbar when the sidebar is hidden; View › Link Details (shift-command-I) opens the link details
  • Link details: the chain and its three numbers share one card, and each cause hangs under the link that broke, with a small pointer to it and the button that fixes it
  • Email one-time-code access protection for published services
  • Changes made in the Cloudflare dashboard are detected at launch, with two repair options
  • Local service discovery and an embedded web view
  • Appearance (system / light / dark) and nine interface languages, applied immediately
  • Free plan publishes up to 2 services; Pro has no limit and adds access protection (Settings › License)
  • Automatic updates
