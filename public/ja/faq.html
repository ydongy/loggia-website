よくある質問

答えが見つかりませんか。何が問題で、どのボタンで直せるかはアプリ自体が表示します。まずサービスか経路の詳細を開いてください。

基本

Loggia は無料ですか。

無料版があります。インターネットに公開できるサービスは 2 つまでで、新たにアクセス保護をオンにすることはできません。Pro は買い切りで、これらの制限がなくなります。価格をご覧ください。

何が必要ですか。

macOS 26 以降の Mac、Cloudflare アカウント、そして Cloudflare で管理しているドメインが 1 つ以上必要です。

Cloudflare への支払いは必要ですか。

公開には Cloudflare Tunnel を使い、これは無料です。アクセス保護にはアカウントで Zero Trust を設定する必要がありますが、無料プランで足ります。ドメインの料金は、通常どおりレジストラから請求されます。

Mac は起動したままにする必要がありますか。

はい。サービスは Mac 上で動き続け、Loggia はそれに公開アドレスを与えるだけです。Mac がスリープ中、電源オフ、オフラインのときは、アドレスにアクセスできません。コネクタはログイン時に起動するので、Mac が復帰すればサービスもすぐに戻ります。

通信はそちらのサーバーを経由しますか。

いいえ。訪問者は Cloudflare を経由して、お客様の Mac に直接アクセスします。Loggia 自身のサーバーはなく、通信の内容も見ません。プライバシーポリシーをご覧ください。

Cloudflare と API トークン

API トークンにはどの権限が必要ですか。

初回設定または 設定 › Cloudflare で Cloudflare でトークンを作成 をクリックします。必要な権限があらかじめ選択されたテンプレートが開くので、確認するだけです。テンプレートには次の権限が含まれます。

Account › Cloudflare Tunnel › Edit必須
Zone › DNS › Edit必須。Zone Resources は使うドメインだけに絞れます。
Account › Access: Apps and Policies › Edit任意。アクセス保護に使います
Account › Access: Organizations, Identity Providers, and Groups › Edit任意。Loggia がメールのコードによるログインを代わりに設定できるようになります

設定 › Cloudflare には各権限の一覧があり、トークンを自分で作成したい場合は 権限リストをコピー を使えます。トークンは Mac のキーチェーンにだけ保存されます。

トークンの権限を直したのに、Loggia がまだ権限が足りないと表示します。

Cloudflare での変更が反映されるまで 1、2 分かかります。少し待ってから、設定 › Cloudflare で もう一度確認 をクリックしてください。

アクセス保護をオンにできないのはなぜですか。
  • アクセス保護は Pro の機能です。
  • 先にサービスを公開する必要があります。
  • トークンに、上記の Access の権限が 2 つとも必要です。
  • Cloudflare アカウントで Zero Trust を設定する必要があります。無料プランで足ります。設定したら、設定 › Cloudflare で もう一度確認 をクリックしてください。
アクセス保護をオンにすると、誰がサービスを開けますか。

指定したメールアドレスの人だけです。@example.com のように追加すると、そのドメインの全員が対象になります。訪問者にはメールでワンタイムコードが届きます。ログインは初期設定で 24 時間有効で、変更できます。

Pro では、自宅やオフィスのインターネットアドレスなどを信頼するネットワークとして追加することもできます。信頼するネットワークからの訪問者はコードなしで開けます。同じ Wi-Fi やモバイルネットワークを使う他の人も同様です。

すでに使っているドメインを Loggia が上書きしませんか。

黙って上書きすることはありません。ドメインがすでに別の場所を指している場合、Loggia は処理を止め、変更する前に確認します。

Pro とライセンス

1 つのライセンスで何台の Mac に使えますか。

2 台です。別の Mac で使うには、先にライセンスが有効な Mac のどちらかで、設定 › ライセンス の 無効化 をクリックしてください。

Pro にはインターネット接続が必要ですか。

有効化のときは必要です。その後、Loggia は 1 日に 1 回ライセンスを確認します。ライセンスサーバーに接続できない場合も、最後に確認できてから 30 日間は Pro が使え、Mac がオンラインに戻れば自動で元に戻ります。

ライセンスはどのバージョンに使えますか。

1.x のすべてのバージョンです。アップデート自体は、どちらのプランでも無料です。

返金してもらえますか。

はい、購入から 14 日以内であれば可能です。申請方法と、その後のライセンスの扱いは返金ポリシーに記載しています。

返金後や、ライセンスが無効になった場合はどうなりますか。

Loggia は無料版に戻ります。公開が止まるものはなく、公開済みのサービスは動き続けます。無料版で管理されるのは、一覧の最初の 2 つの公開済みサービスだけです。それ以外のサービスも動き続けますが、Loggia はその確認を止め、管理対象外 と表示します。これらの公開を停止することは引き続きできます。すでにオンになっているアクセス保護は機能し続け、オフにすることはできますが、変更はできません。再び Pro にアップグレードすると、すべて元に戻ります。

トラブルシューティング

サービスが停止中と表示されます。何から確認すればよいですか。

サービスを開いてください。経路のどこが切れているか（ローカルのサービス、ドメインのレコード、Mac 上のコネクタ、Cloudflare のいずれか）、その理由、そして直すためのボタンを Loggia が表示します。新しいドメインのレコードは、反映まで数分かかることがあります。

Loggia に、プロキシアプリが接続を横取りしていると表示されます。

拡張モードや TUN モードで Fake-IP を使っていると、プロキシアプリは argotunnel.com に偽のアドレスを返すため、cloudflared は Cloudflare への接続を最大 2 本しか保てないか、まったく接続できません。cloudflared が Cloudflare に接続できないとき、Loggia はこれを確認し、確かなときだけプロキシアプリについて表示します。プロキシアプリで:

  1. argotunnel.com と cftunnel.com を直接接続にします。
  2. +.argotunnel.com を Fake-IP フィルタ（fake-ip-filter）に追加して、Cloudflare の実際のアドレスに解決されるようにします。Fake-IP モードでは直接接続のルールだけでは足りません。
  3. Loggia に表示された 再接続、もう一度試す、または 再起動 をクリックします。

公開サービスの状態はインターネット側から確認しているため、プロキシアプリの影響を受けません。公開したばかりのドメインがほかでは開けるのにこの Mac では開けない場合、プロキシアプリが最長 30 分、存在しないものとして覚えていることがあります。そのドメインも Fake-IP フィルタに追加するか、プロキシアプリの DNS キャッシュを消去してください。

コネクタの動作はどこで確認できますか。

設定 › コネクター で、cloudflared がインストールされて動いているか、そのバージョン、最後の終了コード、ログを確認できます。問題が続く場合は、そこから診断情報を書き出せます。

アップデートとアンインストール

Loggia はどうやってアップデートしますか。

Loggia は 1 日に 1 回、新しいバージョンを確認します。新しいバージョンがある場合は変更点を表示し、ダウンロード、インストール、再起動まで行えます。すぐに確認するには、設定 › 情報 で アップデートを確認 をクリックします。毎日の確認を止めるには、同じ画面で アップデートを自動的に確認 をオフにします。設定とサービスはそのまま残り、アップデートはどちらのプランでも無料です。各バージョンの変更点は変更履歴にあります。

Loggia を完全にアンインストールするには。
  1. 設定 › Cloudflare で すべて削除… をクリックし、Loggia が作成したドメインのレコード、ルート、アクセス保護を Cloudflare から削除します。
  2. Loggia を終了し、「アプリケーション」フォルダからゴミ箱に移動します。
  3. ターミナルで launchctl bootout gui/$(id -u)/com.useloggia.app.cloudflared を実行し、~/Library/Application Support/Loggia、~/Library/Logs/Loggia、~/Library/LaunchAgents/com.useloggia.app.cloudflared.plist を削除します。
  4. キーチェーンアクセスで「Loggia」の項目を削除します。
