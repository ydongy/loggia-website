자주 묻는 질문

답을 찾지 못했나요? 앱이 무엇이 문제인지, 어떤 버튼으로 고칠 수 있는지 직접 알려 줍니다. 먼저 서비스나 링크 상세 정보를 열어 보십시오.

기본

Loggia는 무료인가요?

무료 플랜은 무료입니다. 무료 플랜은 최대 2개의 서비스를 인터넷에 공개할 수 있으며, 새로운 접근 보호를 켤 수 없습니다. Pro는 일회성 구매로 이 제한을 없앱니다. 가격을 참고하십시오.

무엇이 필요한가요?

macOS 26 이상이 설치된 Mac, Cloudflare 계정, 그리고 Cloudflare에서 관리하는 도메인이 하나 이상 필요합니다.

Cloudflare에 비용을 내야 하나요?

공개에는 무료인 Cloudflare Tunnel을 사용합니다. 접근 보호를 쓰려면 계정에 Zero Trust를 설정해야 하며, 무료 요금제로 충분합니다. 도메인 비용은 평소처럼 등록 기관에서 청구됩니다.

Mac을 계속 켜 두어야 하나요?

네. 서비스는 Mac에서 계속 실행되고, Loggia는 공개 주소만 제공합니다. Mac이 잠자기 상태이거나 꺼져 있거나 오프라인이면 주소에 접속할 수 없습니다. 커넥터는 로그인할 때 시작되므로, Mac이 다시 켜지면 서비스도 바로 돌아옵니다.

트래픽이 개발자의 서버를 거치나요?

아니요. 방문자는 Cloudflare를 거쳐 Mac으로 직접 접속합니다. Loggia에는 자체 서버가 없으며 사용자의 트래픽을 볼 수 없습니다. 개인정보 처리방침을 참고하십시오.

Cloudflare와 API 토큰

API 토큰에 어떤 권한이 필요한가요?

초기 설정 화면이나 설정 › Cloudflare에서 Cloudflare에서 토큰 만들기를 클릭합니다. 권한이 미리 선택된 템플릿이 열리므로 확인만 하면 됩니다. 템플릿에는 다음 권한이 포함됩니다.

Account › Cloudflare Tunnel › Edit필수
Zone › DNS › Edit필수. Zone Resources는 사용하는 도메인으로 제한할 수 있습니다.
Account › Access: Apps and Policies › Edit선택. 접근 보호에 필요합니다.
Account › Access: Organizations, Identity Providers, and Groups › Edit선택. Loggia가 이메일 코드 로그인을 대신 설정할 수 있습니다.

설정 › Cloudflare에는 각 권한이 나열되어 있으며, 토큰을 직접 만들려면 권한 목록 복사를 사용할 수 있습니다. 토큰은 Mac의 키체인에만 저장됩니다.

토큰 권한을 방금 고쳤는데 Loggia에서 여전히 권한이 없다고 합니다.

Cloudflare의 변경 사항은 적용되기까지 1~2분이 걸립니다. 잠시 기다린 후 설정 › Cloudflare에서 다시 확인을 클릭하십시오.

접근 보호를 켤 수 없는 이유는 무엇인가요?
  • 접근 보호는 Pro 기능입니다.
  • 서비스를 먼저 공개해야 합니다.
  • 토큰에 위에 나열된 두 가지 Access 권한이 모두 있어야 합니다.
  • Cloudflare 계정에 Zero Trust가 설정되어 있어야 합니다. 무료 요금제로 충분합니다. 설정한 후 설정 › Cloudflare에서 다시 확인을 클릭하십시오.
접근 보호를 켜면 누가 서비스를 열 수 있나요?

지정한 이메일 주소만 열 수 있습니다. @example.com을 추가하면 해당 도메인의 모든 사용자가 열 수 있습니다. 방문자는 이메일로 일회용 코드를 받습니다. 로그인은 기본적으로 24시간 유지되며, 이 시간은 변경할 수 있습니다.

Pro에서는 집이나 사무실의 인터넷 주소 같은 신뢰하는 네트워크도 추가할 수 있습니다. 신뢰하는 네트워크에서 오는 방문자는 코드 없이 열 수 있으며, 같은 Wi-Fi나 모바일 네트워크를 쓰는 다른 사람도 마찬가지입니다.

Loggia가 이미 사용 중인 도메인을 덮어쓰나요?

몰래 덮어쓰지 않습니다. 도메인이 이미 다른 곳을 가리키고 있으면 Loggia는 멈추고, 무엇이든 변경하기 전에 먼저 묻습니다.

Pro와 라이선스

라이선스 하나로 몇 대의 Mac에서 사용할 수 있나요?

2대입니다. 다른 Mac에서 사용하려면 먼저 라이선스가 활성화된 Mac 중 한 대의 설정 › 라이선스에서 비활성화를 클릭하십시오.

Pro를 사용하려면 인터넷 연결이 필요한가요?

활성화할 때는 필요합니다. 그 후에는 Loggia가 하루에 한 번 라이선스를 확인합니다. 라이선스 서버에 연결할 수 없으면 마지막으로 확인에 성공한 시점부터 30일 동안 Pro가 계속 작동하며, Mac이 다시 온라인 상태가 되면 자동으로 복구됩니다.

라이선스는 어떤 버전에 적용되나요?

모든 1.x 버전에 적용됩니다. 업데이트 자체는 두 플랜 모두 무료입니다.

환불받을 수 있나요?

네, 구매 후 14일 이내에 가능합니다. 요청 방법과 라이선스에 일어나는 일은 환불 정책에 안내되어 있습니다.

환불하거나 라이선스가 유효하지 않게 되면 어떻게 되나요?

Loggia는 무료 플랜으로 돌아가며, 오프라인이 되는 것은 없습니다. 공개한 서비스는 계속 실행됩니다. 무료 플랜은 목록에서 처음 2개의 공개된 서비스만 관리합니다. 나머지 서비스는 계속 실행되지만, Loggia가 더 이상 확인하지 않으며 관리되지 않음으로 표시합니다. 이 서비스들의 공개를 중지할 수는 있습니다. 이미 켜 둔 접근 보호는 계속 작동하며, 끌 수는 있지만 변경할 수는 없습니다. 다시 Pro로 업그레이드하면 모든 것이 복원됩니다.

문제 해결

서비스가 중단된 것으로 표시됩니다. 어디서부터 확인해야 하나요?

서비스를 여십시오. Loggia가 링크의 어느 부분(로컬 서비스, 도메인 레코드, Mac의 커넥터, Cloudflare)이 끊어졌는지, 그 이유와 이를 고치는 버튼을 보여 줍니다. 새 도메인 레코드는 적용되기까지 몇 분이 걸릴 수 있습니다.

Loggia가 프록시 앱이 연결을 가로채고 있다고 표시합니다.

향상 모드나 TUN 모드에서 Fake-IP를 쓰면 프록시 앱이 argotunnel.com에 가짜 주소를 돌려주므로, cloudflared는 Cloudflare와의 연결을 최대 두 개만 유지하거나 아예 연결하지 못합니다. cloudflared가 Cloudflare에 연결하지 못하면 Loggia가 이를 확인하고, 확인된 경우에만 프록시 앱을 언급합니다. 프록시 앱에서:

  1. argotunnel.com과 cftunnel.com을 직접 연결하도록 설정하십시오.
  2. +.argotunnel.com을 Fake-IP 필터(fake-ip-filter)에 추가해 Cloudflare의 실제 주소로 확인되게 하십시오. Fake-IP 모드에서는 직접 연결 규칙만으로는 부족합니다.
  3. Loggia에 표시된 다시 연결, 다시 시도 또는 다시 시작을 클릭하십시오.

공개 서비스의 상태는 인터넷 쪽에서 확인하므로 프록시 앱의 영향을 받지 않습니다. 방금 게시한 도메인이 다른 곳에서는 열리는데 이 Mac에서만 열리지 않으면, 프록시 앱이 최대 30분 동안 없는 도메인으로 기억하고 있을 수 있습니다. 그 도메인도 Fake-IP 필터에 추가하거나 프록시 앱의 DNS 캐시를 지우십시오.

커넥터가 무엇을 하고 있는지 어디서 볼 수 있나요?

설정 › 커넥터에서 cloudflared의 설치 및 실행 여부, 버전, 마지막 종료 코드, 로그를 볼 수 있습니다. 같은 문제가 계속되면 그곳에서 진단 정보를 내보낼 수 있습니다.

업데이트와 제거

Loggia는 어떻게 업데이트하나요?

Loggia는 하루에 한 번 새 버전을 확인합니다. 새 버전이 있으면 변경 내용을 보여 주고, 다운로드, 설치, 재실행까지 대신 할 수 있습니다. 바로 확인하려면 설정 › 정보에서 업데이트 확인을 클릭합니다. 매일 확인하지 않으려면 같은 곳에서 업데이트 자동 확인을 끕니다. 설정과 서비스는 그대로 유지되며, 업데이트는 두 플랜 모두 무료입니다. 버전별 변경 내용은 변경 사항에서 볼 수 있습니다.

Loggia를 완전히 제거하려면 어떻게 하나요?
  1. 설정 › Cloudflare에서 모두 제거…을 클릭해 Cloudflare에서 Loggia의 도메인 레코드, 라우트, 접근 보호를 삭제합니다.
  2. Loggia를 종료하고 응용 프로그램 폴더에서 휴지통으로 옮깁니다.
  3. 터미널에서 launchctl bootout gui/$(id -u)/com.useloggia.app.cloudflared를 실행한 다음 ~/Library/Application Support/Loggia, ~/Library/Logs/Loggia, ~/Library/LaunchAgents/com.useloggia.app.cloudflared.plist를 삭제합니다.
  4. 키체인 접근에서 “Loggia” 항목을 삭제합니다.
