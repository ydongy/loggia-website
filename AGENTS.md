# AGENTS.md

## What it is

The static website of Loggia (`https://useloggia.com`): home, FAQ, Terms of Service, Privacy Policy, Refund Policy
and changelog in nine languages. Plain HTML generated by Python (standard library only) from `i18n/*.json` and
`changelog.json`, committed in `public/` and served by Cloudflare Workers static assets.

## Sources of truth

- `docs/content.md`: which text lives where, and the Facts table that `scripts/check_facts.py` enforces. Facts
  originate in the product's own (unpublished) facts list; our table is the public mirror.
- `docs/design.md`: palette, typography, components and layout, matching `public/style.css`.
- `docs/adr/`: the decisions behind the shape of the site. Read `docs/adr/README.md` first.
- `docs/contracts.md`: `changelog.json` format and the addresses the app links to.
- English (`i18n/en.json`) is the reference for every translation. The Terms of Service follow the app's license text.

Docs win over code.

## Directory boundaries

```
i18n/        languages.json, check-config.json, one <code>.json per language (the copy)
changelog.json  release history, written by the product's release tooling (PRs), never by hand; keep its format
public/      the generated site and its static assets; commit it with the source change
scripts/     build.py (Loggia settings, home page), check_facts.py, export-og.sh
scripts/sitekit/  vendored generator and checks; never edit here, re-vendor with sitekit's vendor.sh
design/      og.html, the source of public/og.png
docs/        content.md, design.md, contracts.md, adr/
```

Generated HTML and `scripts/sitekit/` are never edited by hand.

## Commands

```
python3 scripts/sitekit/check_i18n.py
python3 scripts/build.py
git diff --exit-code public/
python3 scripts/sitekit/check_site.py
python3 scripts/check_facts.py
python3 scripts/sitekit/preview.py
```

CI (`.github/workflows/ci.yml`) runs the first five; `pr-title.yml` checks the PR title.

## Project rules

- Python standard library only, no Node dependency, no framework (`docs/adr/0001-no-framework.md`).
- No cookies, no third-party scripts or fonts; Cloudflare Web Analytics is the only analytics (`docs/adr/0008-cloudflare-web-analytics.md`).
- Every page has exactly one address; never add a redirect, alias or `_redirects` file.
- Change the copy in `i18n/en.json` first, then all eight other files with the same structure, tags and links;
  no em or en dashes. Legal pages keep their translation note.
- A change to a fact (number, price, window) goes into the Facts table in `docs/content.md` in the same pull
  request.
- A Content-Security-Policy change is an ADR (`docs/adr/0004-content-security-policy.md`).

## Commits and pull requests

Conventional Commits for commit messages and PR titles: `feat|fix|docs|refactor|perf|test|build|ci|chore|revert(scope)!: subject`
(scopes in `docs/contracts.md`). Branch `<type>/<issue>-<slug>`. The maintainer squash-merges. Do not commit or push
unless asked. Update `CHANGELOG.md` under `## [Unreleased]` for user-visible changes.

## Issues and pull requests

`gh issue create` and `gh pr create --body` skip the issue forms and the pull request template, so write their
structure yourself. Search open issues first; one issue is one problem.

- Issue title: one short sentence that says the problem or the outcome, in English or Simplified Chinese. No type
  prefix such as `[feat]`; the label carries the type.
- Bug, `--label bug`: `## What happened`, `## What you expected`, `## Steps to reproduce`,
  `## Version and environment` (page address, language, browser and operating system).
- Feature or improvement, `--label enhancement`: `## Problem`, `## Proposed solution`,
  `## Alternatives considered` (when there were any), `## Done when`.
- Documentation, `--label documentation`: `## Where`, `## What is missing, unclear or wrong`, `## Suggested change`.
- Labels: `accessibility` marks screen-reader, keyboard and contrast work, together with `enhancement` or `bug`.
- Pull request: the title is the Conventional Commits subject (it becomes the squash commit). The body has
  `## Summary` (what changes and why), `## Related issue` (`Closes #<n>`), `## How tested` (the commands run and
  their results, and what was not run) and `## Checklist`:
  `- [ ] PR title follows Conventional Commits`, `- [ ] Tests pass`,
  `- [ ] Documentation updated where behavior changed`, ticked only when true.

## Red lines

- Credentials never appear in PRs, issues, logs, reports or chat.
- Deploys happen only from `main` through Cloudflare Workers Builds. Releases, signing and anything sent to an
  external service need the maintainer's confirmation.
- Review `git status` and stage specific files; no blind `git add -A` of unknown files.
